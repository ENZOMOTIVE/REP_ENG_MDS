In this exercise sheet, we look at reproducibility engineering when working with Large
Language Models (LLMs). Calling an LLM raises three practical questions: how do we
hand the container an API key without risking to leak it, how do we make a model’s
output as reproducible as possible, and how do we make sure the output has the structure
we expect? We work with a small model (Gemma 3 1B) served locally by llama.cpp, so
everything runs on the CPU requiring only a few GB of RAM.

2 Keeping a Secret
When you call a remote LLM, you authenticate with an API key. Because the key is tied
to billing and access, it must be kept secret: it should never be hard-coded in the source
code, copied into an image, or committed to git. Instead, we inject it into the container
at run time. In LabSession10/secrets/ we provide three small demos that each hand
a container the same (dummy) key three different ways. They run offline, so no real key
or network is needed.

3 Reproducible LLM Outputs
Bydefault, anLLM’soutputisnon-deterministic: thesamepromptcanproducedifferent
output each time. In this exercise, we look at two request parameters that help us make
the output deterministic: temperature and seed.
3.1 Starting the Model Server
The directory LabSession10/llm/ contains a docker-compose.yml that downloads a
small LLM (Gemma 3 1B, quantised to Q4_K_M) and serves it with llama.cpp. Its API
is addressable via the OpenAI specification, so we can use the openai Python client.
Specifically, we are using the Chat Completions API in this exercise.
If you are working on narrow-sea, the server is already running.
If you are working locally, set up the container as follows:
Terminal Session bash
user@host$ cd LabSession10/llm
user@host$ docker compose up -d
In both cases, the server listens on port 11434 (i.e., the address is 127.0.0.1:11434).
Next, set up the Python client code:
Terminal Session bash

user@host$ pip install -r requirements.txt
In the following, we use the command python. On narrow-sea, use python3.
On your own machine, it depends on its configurations.

4 Structured Outputs
Often we need the model’s answer in a specific shape, e.g., a JSON instance matching
a given schema. There are two ways to achieve this. We can put the schema in the
prompt and hope the model complies, or we can use constrained decoding (structured
outputs), where the tool restricts generation to tokens allowed by a grammar derived
from the schema, so the output is valid by construction. Both variants are provided in
the directory LabSession10/structured_outputs/; the server from Exercise 3 must be
running.
Both scripts ask for the smallest number that satisfies the same schema:
schema
{
"type": "integer",
"anyOf": [
{ "type": "integer", "minimum": 3, "maximum": 1 },
{ "type": "integer", "minimum": 12000, "maximum": 12002 }
]
}
The first branch (minimum: 3, maximum: 1) can never be satisfied, so the only valid
instances are 12000, 12001, and 12002; the smallest valid answer is 12000.
4.1 Schema in the Prompt
Run the prompt-only variant a few times:
Terminal Session bash
user@host$ python schema_in_prompt.py -i 5
Does the model always return a valid instance? Why is that not guaranteed?
4.2 Constrained Decoding
Now run the structured-outputs variant, which passes the schema via response_format
so the server enforces it during decoding:
Terminal Session bash
user@host$ python structured_output.py -i 5
How does the result differ, and what exactly is now guaranteed?

4.3 oneOf vs. anyOf
Constrained decoding is only as reliable as the translation from schema to grammar,
and not every tool supports every JSON Schema feature. We provide two schemas in
structured_outputs/schemas/ that are identical except that one uses oneOf and the
other anyOf. Convert both to llama.cpp’s GBNF grammar with the provided converter
script and compare:
Terminal Session bash
user@host$ python json_schema_to_grammar.py schemas/number_oneof.json \
> oneof.gbnf
user@host$ python json_schema_to_grammar.py schemas/number_anyof.json \
> anyof.gbnf
user@host$ diff oneof.gbnf anyof.gbnf
What does the diff tell you, and what does it imply for reproducibility?
